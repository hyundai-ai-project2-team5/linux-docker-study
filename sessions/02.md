# 시작하기: Ubuntu 터미널 열기

이 교재는 **Windows에 Ubuntu를 이미 설치한 상태**에서 이어서 진행해요. (PowerShell을 관리자 권한으로 열어서 설치하는 방식이에요.)

## 1단계. 설치되어 있는지 확인하기

**Windows PowerShell**을 열어서 아래를 입력해요.

```powershell
wsl -l -v
```

결과 목록에 `Ubuntu`가 있으면 설치가 잘 된 거예요. 예를 들면 이런 모양이에요.

```
  NAME              STATE           VERSION
* docker-desktop    Running         2
  Ubuntu            Stopped         2
```

- `Ubuntu`가 **목록에 있으면** 성공이에요. `STATE`가 `Stopped`(멈춤)여도 괜찮아요. 들어가면 자동으로 켜져요. `VERSION`은 2면 좋아요.
- 맨 앞의 `*`는 **"기본"** 이라는 표시예요. 위 예시처럼 `Ubuntu`가 아닌 다른 것(예: `docker-desktop`)에 `*`가 붙어 있어도 괜찮아요. Docker Desktop을 설치했다면 흔한 모습이에요. 2단계에서 Ubuntu로 **직접** 들어가는 방법을 알려 줄게요.
- 목록에 `Ubuntu`가 **없으면** 관리자 권한 PowerShell에서 `wsl --install -d Ubuntu`를 입력해요. 끝나면 컴퓨터를 **재부팅**하고 다시 확인해요.

## 2단계. Ubuntu 터미널 열기 (들어가는 방법)

**방법 1. 시작 메뉴 (가장 쉬워요)**

1. Windows **시작 메뉴**를 열고 **Ubuntu**를 검색해요.
2. **Ubuntu**를 눌러 실행하면 검은 창이 열려요. 이게 Ubuntu 터미널이에요.

**방법 2. PowerShell에서 들어가기**

PowerShell에서 아래를 입력해요.

```powershell
wsl -d Ubuntu
```

`-d`는 "이 리눅스로 들어가 줘"라는 뜻이에요. 이름(`Ubuntu`)을 정확히 써요.

> `wsl`만 입력하면 **기본(`*`)** 으로 표시된 리눅스가 열려요. 기본이 `docker-desktop`이면 Ubuntu가 아니라 도커용 작은 리눅스에 들어가서 `nano` 같은 명령이 없어요. 앞으로 `wsl`만 입력해도 Ubuntu가 열리게 하려면 PowerShell에서 한 번만 이렇게 입력해요.
>
> ```powershell
> wsl --set-default Ubuntu
> ```

**처음 열었을 때**는 **사용자 이름**과 **비밀번호**를 만들라고 해요.

- 비밀번호를 입력할 때 **화면에 아무것도 안 보이는 게 정상**이에요. 그냥 입력하고 Enter를 눌러요.
- 이 비밀번호는 나중에 관리자 권한이 필요할 때 써요. 잊지 않게 적어 둬요.

## 3단계. Ubuntu 안에 들어왔는지 확인하기

아래처럼 생긴 한 줄이 보이면 Ubuntu 터미널에 들어온 거예요.

```
내이름@컴퓨터이름:~$
```

(`내이름`과 `컴퓨터이름` 자리에는 **내 사용자 이름**과 **내 컴퓨터 이름**이 나와요. 사람마다 달라요.)

다음 두 줄을 입력해서 확인해 봐요.

```bash
whoami
cat /etc/os-release
```

- `whoami`는 내 사용자 이름을 알려 줘요.
- 두 번째 결과에 `Ubuntu`라는 글자가 보이면 성공이에요.

**위치 확인하기 (`cd ~`)**: PowerShell에서 `wsl -d Ubuntu`로 들어오면 **PowerShell이 있던 Windows 폴더**에서 시작할 수 있어요. 이런 프롬프트가 보이면 그런 경우예요.

```
내이름@컴퓨터이름:/mnt/c/WINDOWS/system32$
```

`/mnt/c/...`는 Ubuntu 안에서 보이는 **Windows의 C 드라이브**예요. Ubuntu에 들어온 건 맞아요. 하지만 **이 교재의 실습 파일은 Windows 폴더가 아니라 Ubuntu의 내 폴더(홈)에 만들어요.** 특히 `system32`는 Windows 시스템 폴더라서 파일을 만들면 안 돼요. 그래서 들어오면 **제일 먼저** 이렇게 입력해요.

```bash
cd ~
pwd
```

✅ `/home/내이름`이 나오고 프롬프트가 `내이름@컴퓨터이름:~$`로 바뀌면 준비 끝이에요. (시작 메뉴로 열었다면 보통 처음부터 `~`예요.)

**잘못 들어온 경우**: `Ubuntu`가 안 보이거나, 프롬프트가 `#`로 끝나고 `-sh: ... not found` 같은 메시지가 나오면 Ubuntu가 아닌 다른 리눅스에 들어온 거예요. 당황하지 말고 `exit`를 입력해서 나온 뒤, 위 2단계의 방법 1이나 `wsl -d Ubuntu`로 다시 들어와요.

> **PowerShell과 Ubuntu 터미널은 서로 다른 곳이에요.** 이 교재의 명령은 **전부 Ubuntu 터미널**에서 입력해요. 프롬프트가 `PS C:\>`로 시작하면 PowerShell이니까, `wsl -d Ubuntu`로 Ubuntu에 들어와요.
> 터미널을 끝낼 때는 `exit`를 입력해요. 다음에 다시 시작할 때는 위 2단계의 방법 1이나 방법 2로 들어오면 돼요.

# 1부. 터미널, 셸, 명령어

## 터미널과 셸은 뭘까요?

식당에 비유해 볼게요.

| 용어 | 쉬운 설명 | 식당 비유 |
|---|---|---|
| **터미널** | 글자를 입력하고 결과를 보는 **창** | 주문 단말기 |
| **셸** | 입력한 명령을 **알아듣고 실행해 주는 프로그램** | 주문을 받아 주방에 전달하는 직원 |
| **프롬프트** | "이제 입력하세요"라는 표시 | 다음 손님을 부르는 안내 |

명령어를 입력하고 **Enter**를 누르면 셸이 실행해 줘요. 우리가 쓰는 셸의 이름은 **Bash**예요.

## 명령어는 이렇게 생겼어요

```bash
ls -l /tmp
```

| 부분 | 이름 | 뜻 |
|---|---|---|
| `ls` | 명령어 | **무엇을** 할지 (목록 보기) |
| `-l` | 옵션 | **어떻게** 할지 (자세하게) |
| `/tmp` | 인자 | **무엇에게** 할지 (이 폴더를) |

- 각 부분은 **띄어쓰기**로 구분해요. 띄어쓰기를 빼먹으면 다른 명령이 돼요.
- 옵션은 합칠 수 있어요. `ls -l -a`는 `ls -la`와 같아요.

## 모르는 명령어는 스스로 찾아요

명령어를 전부 외울 필요는 없어요. **찾아보는 방법**만 알면 돼요.

```bash
ls --help        # 간단한 사용법
man ls           # 자세한 설명서 (q 를 누르면 나가요)
```

- `man`이 열렸을 때 **`q`** 를 누르면 나갈 수 있어요. 제일 중요해요!
- Ubuntu(WSL)는 설명서가 일부 빠져 있어서 `No manual entry`라고 나오거나 `minimized`라는 안내가 뜰 수 있어요. 그땐 `--help`를 쓰면 돼요.
- 명령어 이름을 모르고 단어만 안다면 `apropos directory`처럼 검색해요.

## 키보드 요령 세 가지

- **Tab**: 글자 몇 개만 쓰고 Tab을 누르면 자동으로 완성해 줘요. 오타가 줄어요.
- **↑ (위 화살표)**: 방금 입력한 명령을 다시 불러와요.
- **Ctrl + C**: 지금 하는 일을 멈춰요. 화면이 멈춘 것 같을 때 써요.

# 2부. 따라 하면서 배우는 폴더와 파일 (실습 1)

2부는 **설명을 읽고 → 바로 입력하고 → 결과를 눈으로 확인**하는 순서로 이어져요. 위에서부터 차례대로 따라 해 보세요. 마지막에는 우리가 만든 것들을 명령어로 직접 정리(삭제)해 볼 거예요.

## 1단계. 내 위치 알기: `pwd`

리눅스의 폴더는 **나무 모양**이에요. 맨 위에 **`/` (루트)** 가 하나 있고, 그 아래로 가지처럼 폴더가 뻗어 있어요.

```
/
├── home/   내 폴더가 있는 곳 (여기가 내 방이에요)
├── etc/    시스템 설정 파일
├── tmp/    임시로 쓰는 곳
└── usr/    프로그램들
```

우리는 **내 폴더(홈) 안에서만** 연습해요. 시스템 폴더는 보기만 해요.

내가 지금 어느 폴더에 서 있는지 먼저 확인해 봐요.

```bash
pwd
```

```
/home/내이름
```

✅ `/home/내이름`이 나오면 **내 방(홈 폴더)** 에 있는 거예요. 앞으로 길을 잃으면 **`pwd`부터** 입력해요.

> `/mnt/c/...`처럼 나오면 Windows 폴더에 있는 거예요. `cd ~`를 입력해서 내 홈 폴더로 먼저 이동해요. (`cd ~`는 3단계에서 자세히 배워요.)

## 2단계. 주변 둘러보기: `ls`

```bash
ls
ls -l
ls -a
```

- `ls`: 이름만 보여 줘요.
- `ls -l`: 크기, 날짜 등을 **자세히** 보여 줘요.
- `ls -a`: **숨김 파일**까지 보여 줘요.

✅ `ls -a`에는 `.bashrc`처럼 **`.`으로 시작하는 이름**이 더 보여요. 이게 숨김 파일이에요. 보안 기능이 아니라, "목록에서 기본으로 안 보이게" 해 둔 것뿐이에요.

## 3단계. 돌아다니기: `cd`

`cd`로 폴더를 옮겨 다닐 수 있어요. 한 줄씩 입력하면서 `pwd`로 위치를 확인해 봐요.

```bash
cd /tmp
pwd
cd ~
pwd
cd ..
pwd
```

✅ 순서대로 `/tmp` → `/home/내이름` → `/home`이 나와요.

| 기호 | 뜻 |
|---|---|
| `~` | 내 홈 폴더 (그냥 `cd`만 입력해도 홈으로 와요) |
| `..` | 한 칸 위 폴더 |
| `.` | 지금 폴더 |

(`cd`는 성공해도 아무 말도 안 해요. 잘 갔는지는 `pwd`로 확인해요.)

방금 `cd /tmp`처럼 **`/`부터 쓴 주소**를 **절대 경로**라고 해요. 어디서든 똑같은 곳을 가리켜요.

반대로 **지금 있는 곳에서 출발하는 주소**는 **상대 경로**예요. 앞으로 `docs/memo.txt`처럼 쓰는 게 상대 경로예요.

| 종류 | 예 | 비유 |
|---|---|---|
| 절대 경로 | `/home/내이름/docs` | "서울시 ○○구 ○○로 1번지" |
| 상대 경로 | `docs/memo.txt` | "우리 집 옆집" |

다음 단계를 위해 홈 폴더로 돌아와요.

```bash
cd ~
pwd
```

## 4단계. 연습 폴더 만들기: `mkdir`

앞으로 쓸 연습 공간을 만들고 그 안으로 들어가 봐요.

```bash
mkdir linux-study
ls
cd linux-study
pwd
ls
```

✅ 첫 `ls`에는 `linux-study`가 새로 보여요. 들어간 뒤 `pwd`는 `/home/내이름/linux-study`이고, 두 번째 `ls`는 **아무것도 안 나와요.** 방금 만든 **빈 폴더**니까요.

이어서 그 안에 메모를 담을 폴더를 하나 더 만들어요.

```bash
mkdir docs
ls
```

✅ `docs`가 보여요.

### 내가 만든 폴더를 Windows 화면에서 보고 싶다면

방금 만든 `linux-study`는 Windows의 `C:` 드라이브가 아니라 **Ubuntu 전용 공간(가상 리눅스 안)** 에 있어요. 그래서 평소처럼 내 PC 폴더에서 찾으면 안 보여요. 대신 Ubuntu 터미널에서 이렇게 입력하면 **Windows 탐색기로 지금 폴더를 열어 줘요.**

```bash
cd ~/linux-study
explorer.exe .
```

- `explorer.exe`는 Windows 탐색기이고, 뒤의 `.`(점)은 **지금 폴더**예요. 점 앞에 띄어쓰기가 있어요.
- 탐색기가 열리면 `docs` 폴더가 보여요. 터미널에서 만들고 지우는 걸 탐색기와 나란히 보면 이해가 쉬워요.

> 탐색기는 **구경하는 용도**로 써요. 폴더와 파일은 이 교재처럼 터미널에서 만들고 지워요.

## 5단계. 메모 만들고 읽기

이번에는 `docs` 폴더 안에 **메모 파일**을 만들고, 만든 파일을 열어서 읽어 볼 거예요. 먼저 **내가 지금 어디에 있는지**부터 확인해요.

```bash
pwd
```

```
/home/내이름/linux-study
```

지금 우리는 `linux-study` 안에 있고, 그 안에 방금 만든 `docs` 폴더가 있어요. 그림으로 보면 이래요.

```
linux-study      ← 지금 내가 서 있는 곳
└── docs         ← 메모를 만들 곳
```

### 5-1. 글을 화면에 말하게 하기: `echo`

`echo`는 **내가 쓴 글을 그대로 말해 주는** 명령이에요.

```bash
echo "오늘은 리눅스 첫날이에요"
```

```
오늘은 리눅스 첫날이에요
```

✅ 입력한 글이 **화면에** 그대로 나와요. 이 글을 화면이 아니라 **파일에** 적고 싶다면, 뒤에 `>`와 파일 위치를 붙여요.

### 5-2. 글을 파일에 적기: `echo "글" > 파일 위치`

```bash
echo "오늘은 리눅스 첫날이에요" > docs/memo.txt
```

`>`는 **"화면 말고 여기에 적어 줘"** 라는 뜻이에요. 그 뒤의 `docs/memo.txt`가 **파일을 만들 위치(경로)** 예요. 이 경로를 풀어서 읽어 봐요.

```
docs/memo.txt
 │      └─ memo.txt 라는 파일을
 └─ docs 폴더 안에
```

내가 지금 `linux-study`에 서 있으니까, **거기서부터 출발해서** `docs` 폴더로 들어가 `memo.txt`를 만든 거예요. (2부 3단계에서 배운 **상대 경로**예요.)

잘 만들어졌는지 `ls`로 확인해 봐요. 폴더 이름을 뒤에 쓰면 **그 폴더 안**을 보여 줘요.

```bash
ls docs
```

```
memo.txt
```

✅ `docs` 안에 `memo.txt`가 생겼어요. 화면에는 아무 말도 안 나왔지만, 글은 파일 안에 적혀 있어요.

> **경로가 헷갈릴 때는** `pwd`로 내 위치를 확인하고, "내 위치에서 파일까지 어떻게 가지?"를 적으면 돼요. 만약 `cd docs`로 `docs` 안에 들어가 있다면 그냥 `memo.txt`라고만 써도 돼요. 지금은 `linux-study`에 있으니까 `docs/memo.txt`예요.

### 5-3. 파일 내용 읽기: `cat`

파일 안에 정말 글이 적혀 있는지 열어 봐요. **`cat 파일 위치`** 는 파일 내용을 화면에 보여 줘요.

```bash
cat docs/memo.txt
```

```
오늘은 리눅스 첫날이에요
```

✅ 아까 적은 글이 그대로 나와요. 파일을 만들고(5-2) 읽는(5-3) 데까지 한 바퀴를 돌았어요. (`cat`도 `ls`처럼 **어디에 있는 파일인지** 경로를 알려 줘야 해요.)

### 5-4. 빈 파일 만들기: `touch`

이번에는 **글 없이 파일만** 만들어 볼게요. **`touch 파일 위치`** 는 **내용이 없는 빈 파일**을 만들어요.

```bash
touch docs/empty.txt
ls docs
```

```
empty.txt  memo.txt
```

✅ `docs` 안에 파일이 두 개가 됐어요. 이제 이 두 파일이 어떻게 다른지 `ls -l`로 크기를 비교해 봐요.

```bash
ls -l docs
```

```
-rw-r--r-- 1 내이름 내이름  0 ... empty.txt
-rw-r--r-- 1 내이름 내이름 36 ... memo.txt
```

✅ 가운데쯤 있는 숫자가 **파일 크기**예요. `empty.txt`는 **0**(비어 있음), `memo.txt`는 글이 들어 있어서 **0이 아니에요.**

그럼 빈 파일을 `cat`으로 열면 어떻게 될까요?

```bash
cat docs/empty.txt
```

✅ **아무것도 안 나와요.** 오류가 아니라, 보여 줄 내용이 없어서 그래요. 아까 `memo.txt`를 `cat`했을 때와 비교해 보세요.

### 5단계 정리

| 하고 싶은 일 | 명령 |
|---|---|
| 글을 화면에 보기 | `echo "글"` |
| 글을 파일에 적어서 만들기 | `echo "글" > docs/memo.txt` |
| 빈 파일 만들기 | `touch docs/empty.txt` |
| 파일 내용 읽기 | `cat docs/memo.txt` |
| 폴더 안 목록 보기 | `ls docs`, `ls -l docs` |

지금 `linux-study` 안의 모양은 이래요.

```
linux-study
└── docs
    ├── memo.txt    (글이 있는 파일)
    └── empty.txt   (빈 파일)
```

## 6단계. 복사하기: `cp`

`memo.txt`를 복사해 볼게요. 복사하고 나서 **원본과 복사본이 둘 다 있는지** 눈으로 확인해요.

```bash
cp docs/memo.txt docs/memo-copy.txt
ls docs
cat docs/memo.txt
cat docs/memo-copy.txt
```

✅ `docs`에 `memo-copy.txt`가 **새로 생겼고**, 원본 `memo.txt`도 **그대로** 있어요. 두 파일의 내용이 똑같아요. `cp`는 **복사**라서 원본이 남아요.

폴더도 통째로 복사할 수 있어요. 폴더는 `-r`을 붙여야 해요.

```bash
cp -r docs docs-backup
ls
ls docs-backup
```

✅ `docs-backup` 폴더가 생기고, 그 안에 `docs`와 같은 파일들이 들어 있어요.

> 같은 이름이 이미 있으면 복사할 때 **덮어써요.** 조심하고 싶으면 `cp -i`처럼 `-i`를 붙이면 덮어쓰기 전에 물어봐요.

## 7단계. 옮기기와 이름 바꾸기: `mv`

`mv`는 **이동**이에요. 같은 명령으로 **이름 바꾸기**도 해요.

먼저 이름을 바꿔 봐요.

```bash
mv docs/memo-copy.txt docs/memo-old.txt
ls docs
```

✅ `memo-copy.txt`는 사라지고 `memo-old.txt`가 보여요. 파일은 그대로고 **이름만** 바뀐 거예요.

이번에는 다른 폴더로 옮겨 봐요.

```bash
mkdir archive
mv docs/memo-old.txt archive/
ls docs
ls archive
```

✅ `docs`에서는 `memo-old.txt`가 **없어지고**, `archive`에서 보여요. 복사(`cp`)와 달리 **원본이 옮겨갔어요.**

지금까지 만든 것을 한 번에 훑어봐요. `-R`은 폴더 안까지 전부 보여 줘요.

```bash
ls -R
```

✅ `archive`, `docs`, `docs-backup` 세 폴더와 그 안의 파일들이 한눈에 보여요.

## 8단계. 안전하게 지우기: `rm`

이제 연습하느라 만든 것들을 정리해 볼 차례예요.

> ⚠️ **리눅스에는 휴지통이 없어요.** `rm`으로 지우면 되돌리기 어려워요. 그래서 **확인 → 삭제 → 확인** 순서를 꼭 지켜요.

**지우기 전 확인 순서**

```
pwd(어디지?) → ls(뭐가 있지?) → 지울 것 확인 → rm -i → ls(잘 지워졌나?)
```

먼저 6단계에서 만든 **백업 폴더(`docs-backup`)** 부터 정리해 봐요. 지우기 전에 위치와 안에 든 것부터 확인해요.

```bash
pwd
ls docs-backup
```

```
empty.txt  memo-copy.txt  memo.txt
```

### 이름의 모양으로 한꺼번에 고르기: `*`

파일이 여러 개일 때는 이름의 **모양**으로 한꺼번에 고를 수 있어요.

| 패턴 | 뜻 | 예 |
|---|---|---|
| `*` | 아무 글자 여러 개 | `memo*` → `memo`로 시작하는 이름 전부 |
| `?` | 아무 글자 딱 한 개 | `log?.txt` → `log1.txt`, `logA.txt` |

`docs-backup` 안에서 **`memo`로 시작하는 파일만** 골라 보여 달라고 해 봐요.

```bash
ls docs-backup/memo*
```

```
docs-backup/memo-copy.txt  docs-backup/memo.txt
```

✅ `empty.txt`는 빠지고 **`memo`로 시작하는 두 파일만** 나와요. 패턴이 두 파일만 골라 준 거예요. 이게 바로 **"지울 것 확인"** 단계예요. 이 두 개를 지우는 게 맞다면, 같은 패턴으로 지워요.

> 지우기 전에는 이렇게 **`ls`로 먼저 똑같은 패턴을 입력해서** 뭐가 걸리는지 확인하는 습관이 중요해요.

### 지우기

```bash
rm -i docs-backup/memo*
ls docs-backup
```

- `rm -i`는 파일마다 **"정말 지울까요?"** 하고 물어봐요. `y`를 입력하고 Enter를 누르면 지워져요. (두 번 물어봐요.)

✅ `docs-backup`에 `empty.txt`만 남아요. 확인했던 두 파일이 정확히 지워졌어요.

남은 것도 정리해요. `docs-backup/*`는 **그 폴더 안의 모든 파일**이라는 뜻이에요. 옮겨 두었던 오래된 메모(`archive/memo-old.txt`)도 같이 지워요.

```bash
ls docs-backup/*
rm -i docs-backup/*
rm -i archive/memo-old.txt
ls docs-backup
ls archive
```

✅ 두 폴더가 모두 **텅 비어요.** 빈 폴더는 `rmdir`로 지울 수 있어요. (`rmdir`는 **빈 폴더만** 지우니까 안전해요.)

```bash
rmdir archive docs-backup
ls
```

✅ `docs`만 남아요. 그리고 `docs` 안에는 `empty.txt`와 `memo.txt`가 있어요. 이 파일들은 뒤의 실습에서 계속 쓰니까 **지우지 말고 남겨 두세요.**

# 3부. 따라 하면서 배우는 파일 내용 보기, 파이프, 검색 (실습 2)

3부도 **설명 → 바로 입력 → 결과 확인** 순서로 이어져요. 서버가 남긴 **기록(로그)** 파일을 하나 만들어 놓고, 그 파일로 보고, 저장하고, 찾고, 세어 볼 거예요. 위에서부터 차례대로 따라 해 보세요.

## 1단계. 연습용 로그 파일 만들기

먼저 `linux-study` 폴더에 있는지 확인하고, 연습할 로그 파일을 만들어요.

```bash
cd ~/linux-study
pwd
printf 'INFO start\nERROR disk\nWARN memory\nERROR network\nERROR disk\nINFO end\n' > log.txt
ls
```

- `printf`는 `echo`와 비슷하게 글을 적어 주는 명령이에요. 안에 있는 `\n`은 **"줄 바꿈"** 이에요.
- `> log.txt`는 2부 5단계에서 배운 것처럼 **그 글을 `log.txt` 파일에 적어 줘**라는 뜻이에요.

✅ `ls`에 `log.txt`가 보이면 성공이에요. 이 파일에는 로그 6줄이 들어 있어요.

## 2단계. 파일 내용 보기: `cat`, `head`, `tail`

| 명령 | 하는 일 |
|---|---|
| `cat 파일` | 내용을 **전부** 보여 줘요 |
| `head -n 2 파일` | **앞** 2줄만 |
| `tail -n 2 파일` | **뒤** 2줄만 |
| `less 파일` | 한 화면씩 넘기며 봐요 (`q`로 나가요) |

```bash
cat log.txt
```

```
INFO start
ERROR disk
WARN memory
ERROR network
ERROR disk
INFO end
```

✅ 6줄이 전부 나와요. 이번에는 **앞부분과 뒷부분**만 봐요.

```bash
head -n 2 log.txt
tail -n 2 log.txt
```

```
INFO start
ERROR disk
```

```
ERROR disk
INFO end
```

✅ 첫 번째 결과(`head`)는 **앞 2줄**, 두 번째 결과(`tail`)는 **뒤 2줄**이에요.

글이 아주 길 때는 `cat` 대신 `less log.txt`를 써 봐요. 한 화면씩 보여 주고, **`q`를 누르면 나가요.**

이 명령들은 보기만 해서 **원본이 바뀌지 않아요.** 마음 편히 써도 돼요.

## 3단계. 결과를 파일에 저장하기: `>`, `>>`

명령의 결과는 보통 화면에 나와요. 이걸 **파일로 보낼** 수 있어요. 2부에서 메모를 만들 때 썼던 `>`가 바로 이거예요.

| 기호 | 뜻 |
|---|---|
| `>` | 결과를 파일에 저장 (**원래 내용은 지워져요!**) |
| `>>` | 결과를 파일 **끝에 덧붙여요** |

```bash
echo "첫째 줄" > todo.txt
echo "둘째 줄" >> todo.txt
cat todo.txt
```

```
첫째 줄
둘째 줄
```

✅ `>>`로 덧붙였으니 두 줄이 다 있어요. 이번에는 일부러 `>`를 한 번 더 써 봐요.

```bash
echo "새로 쓴 줄" > todo.txt
cat todo.txt
```

```
새로 쓴 줄
```

✅ 앞의 두 줄이 **사라졌어요.** `>`는 파일을 비우고 새로 쓰기 때문이에요. 덧붙이고 싶을 때는 `>>`예요.

> ⚠️ 중요한 내용이 있는 파일 이름에 `>`를 쓰지 않도록 조심해요.
> 오류 메시지만 따로 저장하는 `2>`도 있지만, 지금은 이런 게 있다는 것만 알아 둬요.

## 4단계. 원하는 줄만 찾기: `grep`

로그가 길어지면 눈으로 찾기 어려워요. `grep`은 **글자가 들어 있는 줄만** 골라 줘요. 아까 만든 `log.txt`로 하나씩 해 봐요.

**① 기본: `grep "찾을 글자" 파일`**

```bash
grep "ERROR" log.txt
```

```
ERROR disk
ERROR network
ERROR disk
```

✅ `ERROR`가 들어 있는 줄만 3줄 나와요. (찾는 글자는 **따옴표로** 감싸요.)

**② 대소문자 무시: `-i`**

먼저 소문자로 찾아 봐요.

```bash
grep "error" log.txt
```

✅ **아무것도 안 나와요.** 로그에는 대문자 `ERROR`만 있고, grep은 대소문자를 **구분**하기 때문이에요. (찾는 게 없는 건 오류가 아니라 "그런 줄이 없다"는 뜻이에요.) 이제 `-i`를 붙여요.

```bash
grep -i "error" log.txt
```

✅ 이번에는 `ERROR` 줄 3줄이 나와요. `-i`는 대소문자를 **구분하지 않고** 찾아 줘요.

**③ 줄 번호도 보기: `-n`**

```bash
grep -n "ERROR" log.txt
```

```
2:ERROR disk
4:ERROR network
5:ERROR disk
```

✅ 앞의 숫자가 **몇 번째 줄인지**예요.

**④ 없는 줄 찾기: `-v`**

```bash
grep -v "INFO" log.txt
```

```
ERROR disk
WARN memory
ERROR network
ERROR disk
```

✅ `INFO`가 **없는** 줄만 나와요. (`-v`는 "반대로"예요.)

**⑤ 몇 줄인지 세기: `-c`**

```bash
grep -c "ERROR" log.txt
```

```
3
```

✅ 줄을 보여 주는 대신 **`ERROR`가 있는 줄의 개수**만 알려 줘요. 한 줄에 `ERROR`가 세 번 나와도 그 줄은 1로 세요.

| 옵션 | 뜻 |
|---|---|
| (없음) | 글자가 들어 있는 줄을 보여 줘요 |
| `-i` | 대소문자 구분 안 하고 |
| `-n` | 줄 번호도 같이 |
| `-v` | 글자가 **없는** 줄만 |
| `-c` | 줄이 **몇 개**인지 |

## 5단계. 명령 이어 붙이기: 파이프 `|`

세로선 `|`을 **파이프**라고 불러요. **앞 명령의 결과를 뒤 명령에게 넘겨줘요.** 공장의 컨베이어 벨트와 같아요. 줄 수를 세 주는 `wc -l`과 이어 볼게요.

```bash
cat log.txt | wc -l
grep "ERROR" log.txt | wc -l
```

```
6
3
```

✅ 첫 줄은 `log.txt`를 읽어서(앞) 줄 수를 세니(뒤) **6**이에요. 둘째 줄은 `ERROR` 줄만 골라서(앞) 줄 수를 세니(뒤) **3**이에요. (아까 `grep -c`와 같은 결과예요.)

## 6단계. 정렬하고 개수 세기: `sort`와 `uniq -c`

"**같은 게 몇 번 나왔나?**"를 세고 싶을 때 `sort`와 `uniq -c`를 같이 써요.

- `sort`: 줄을 **정렬**해요.
- `uniq -c`: **바로 이웃한** 같은 줄을 하나로 합치고 개수를 세어 줘요.

일부러 `sort` 없이 먼저 해 봐요.

```bash
grep "ERROR" log.txt | uniq -c
```

```
      1 ERROR disk
      1 ERROR network
      1 ERROR disk
```

✅ `ERROR disk`가 두 번 나왔는데 **합쳐지지 않았어요.** 같은 줄이 **떨어져 있으면** `uniq`가 한 덩어리로 못 봐요. 그래서 **먼저 `sort`로 같은 것끼리 모아 줘요.**

```bash
grep "ERROR" log.txt | sort | uniq -c
```

```
      2 ERROR disk
      1 ERROR network
```

✅ 이제 `ERROR disk`가 **2번**, `ERROR network`가 **1번**이라고 제대로 나와요.

한 줄이 하는 일: `grep`(ERROR 줄만 골라서) → `sort`(정렬하고) → `uniq -c`(개수를 세요)

이 결과를 파일로 저장해 둘게요. 3단계에서 배운 `>`를 이어 붙이면 돼요.

```bash
grep "ERROR" log.txt | sort | uniq -c > report.txt
cat report.txt
```

✅ 방금 본 결과가 화면 대신 `report.txt`에 저장되고, `cat`으로 읽으면 같은 내용이 나와요.

## 7단계. 글 쓰는 편집기: nano

`report.txt`의 맨 위에 제목을 한 줄 넣어 볼게요. 파일을 직접 고치는 프로그램 **nano**를 써요.

```bash
nano report.txt
```

> `nano: command not found`(또는 `not found`)가 나오면 Ubuntu가 아닌 곳에 있거나 nano가 설치되지 않은 거예요. 먼저 '시작하기' 3단계의 **Ubuntu 확인**을 다시 해 봐요. Ubuntu인데도 없다면 `sudo apt update`, `sudo apt install nano`를 차례로 입력해서 설치해요. (비밀번호를 물으면 처음에 만든 비밀번호예요.)

화면이 바뀌면서 파일 내용이 보여요. 키보드 화살표로 맨 윗줄로 가서 바로 글을 쓰면 돼요. 맨 윗줄에 `ERROR 보고서`를 입력하고 **Enter**를 눌러요.

아래쪽에 단축키가 적혀 있어요. (`^`는 `Ctrl`이라는 뜻이에요.)

| 키 | 하는 일 |
|---|---|
| `Ctrl + O` 그리고 `Enter` | **저장** |
| `Ctrl + X` | **종료** (저장 안 했으면 물어봐요) |

`Ctrl + O` → `Enter` → `Ctrl + X` 순서로 저장하고 나와요. 그리고 잘 고쳐졌는지 읽어 봐요.

```bash
cat report.txt
```

```
ERROR 보고서
      2 ERROR disk
      1 ERROR network
```

✅ 맨 윗줄에 `ERROR 보고서`가 있고 그 아래에 개수가 있어요.

## 3부 정리

| 하고 싶은 일 | 명령 |
|---|---|
| 내용 전부 / 앞 / 뒤 보기 | `cat`, `head -n 2`, `tail -n 2` |
| 화면 대신 파일에 저장 / 덧붙이기 | `>`, `>>` |
| 글자가 들어 있는 줄 찾기 | `grep "글자" 파일` (`-i` `-n` `-v` `-c`) |
| 앞 명령의 결과를 뒤 명령에게 | 파이프 `\|` |
| 같은 줄 개수 세기 | `sort` 다음에 `uniq -c` |
| 글 고치기 | `nano 파일` (`Ctrl+O` 저장, `Ctrl+X` 종료) |

# 정리하기

## 한 장 요약

| 주제 | 기억할 것 |
|---|---|
| 터미널과 셸 | 터미널은 **창**, 셸은 명령을 **알아듣는 프로그램** |
| 명령어 | `명령어 + 옵션 + 인자`, 띄어쓰기로 구분 |
| 모를 때 | `명령어 --help`, `man 명령어` (나갈 때 `q`) |
| 위치 | `pwd`로 확인, `cd`로 이동, `~`는 홈, `..`는 한 칸 위 |
| 파일 | `cp` 복사(원본 남음), `mv` 이동·이름 변경, `rm` **되돌릴 수 없음** |
| 지울 때 | `pwd` → `ls` → `rm -i` → `ls` |
| 저장 | `>` 덮어쓰기, `>>` 덧붙이기 |
| 파이프 | `\|` 앞 명령의 결과를 뒤 명령에 넘겨줌 |
| 찾기·세기 | `grep`, `sort` 다음에 `uniq -c`, `wc -l` |
| 편집 | nano: `Ctrl+O` 저장, `Ctrl+X` 종료 |

## 막혔을 때

| 메시지·증상 | 이유와 해결 |
|---|---|
| `command not found` | 이름 오타예요. 다시 확인해요 |
| `No such file or directory` | 경로 오타예요. `pwd`와 `ls`로 확인해요 |
| `Permission denied` | 권한이 없어요. 우리 연습 폴더(홈 안)에서 하고 있는지 확인해요 |
| 엔터를 쳤는데 `>`만 나와요 | 따옴표를 안 닫았어요. `Ctrl + C`로 취소해요 |
| 화면이 멈춘 것 같아요 | `q`(man, less) 또는 `Ctrl + C`를 눌러 봐요 |
| 파일이 갑자기 비었어요 | `>`로 덮어쓰지 않았는지 확인해요 (덧붙일 땐 `>>`) |
| 한글이 깨져요 | PowerShell이 아니라 Ubuntu 터미널인지 확인해요 |

## 복습 체크리스트

- [ ] 터미널과 셸의 차이를 내 말로 설명할 수 있다.
- [ ] `ls -l /tmp`에서 명령어, 옵션, 인자를 구분할 수 있다.
- [ ] 모르는 명령은 `--help`나 `man`으로 찾아본다.
- [ ] `pwd`, `cd`, `ls`로 길을 잃지 않고 다닐 수 있다.
- [ ] 지우기 전에 `pwd`와 `ls`로 확인하는 습관이 있다.
- [ ] `>`와 `>>`의 차이를 안다.
- [ ] 파이프로 `grep`, `sort`, `uniq -c`를 이어 쓸 수 있다.
