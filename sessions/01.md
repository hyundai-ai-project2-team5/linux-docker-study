### 1. 왜 리눅스인가

우리 과정의 최종 산출물에는 **"배포 완료"**가 붙어 있어요. 프로젝트 III는 '역할기반 WMS AI 에이전트(배포 완료)', 프로젝트 IV는 'AI 기반 WMS 통합 플랫폼(배포 완료)'이에요. 과정이 꼽은 핵심 역량 세 가지 중 하나도 **배포·운영력**이고요.

배포는 내 프로그램을 **다른 컴퓨터(서버)에서 계속 돌아가게 하는 일**이에요. 그 서버가 무엇이고 어떻게 다루는지가 앞으로 9회 동안 배울 내용이에요.

> **배포**(deployment)는 서비스를 서버에 올리는 일이고, **배포판**(distribution)은 Ubuntu 같은 리눅스 묶음이에요. 오늘은 두 말이 다 나와요.

#### 과정 일정에서 리눅스를 만나는 곳

| 과정 일정 | 하는 일 | 리눅스를 만나는 지점 | 스터디 |
| --- | --- | --- | --- |
| **지금** · AI 서비스 백엔드 개발 (~12/1) | 재고·입출고 API 서버 | 서버는 포트를 열고 요청을 기다리는 **프로세스** | 4·5회차 |
| 1/11~1/20 · 프로젝트 II | WMS 요청처리 웹앱을 6명이 개발 | 6명의 실행 환경을 똑같이 맞추는 **컨테이너** | 6~9회차 |
| 1/21~2/1 · 배포 및 운영 (6일) | WMS 웹앱 Vercel/AWS 배포, 보안·백업 | 원격 서버에 **SSH**로 접속해 권한·포트·로그 확인 | 3~5회차 |
| 2/2~2/11 · MCP 기반 AI 통합 | 재고 DB와 외부 시스템 MCP 연동 | stdio 방식은 **하위 프로세스와 표준 입출력** | 4회차 |
| 2/12~4/2 · 프로젝트 III·IV | 역할별 에이전트, 통합 플랫폼 (배포 완료) | 배포한 서비스의 프로세스·로그 직접 확인 | 전체 |

배포 및 운영 수업은 6일뿐이에요. 기초를 지금 다져 두면 그때는 배포 자체에 집중할 수 있어요.

#### 근원으로 줄이면 이유는 세 가지예요

1. **배포할 곳은 리눅스이고, 서버에는 화면이 없어요.** 우리 과정의 배포 플랫폼도 리눅스 위에서 돌아요. Vercel의 빌드 이미지는 Amazon Linux 2023 기반이고, AWS는 Amazon Linux라는 배포판을 직접 만들어요. 서버는 모니터 없이 네트워크 너머에 있어서 글자로 주고받는 **셸**로 다뤄요. 글자 명령은 기록하고, 똑같이 반복하고, 자동화할 수 있어요.
2. **컨테이너는 리눅스 커널의 기능이에요.** 도커 컨테이너는 리눅스 커널의 namespace(격리)와 cgroup(자원 제한)으로 울타리를 친 프로세스예요. Windows와 Mac의 Docker Desktop도 리눅스 컨테이너를 돌리려고 안에서 리눅스 커널을 돌려요. 발표자 PC에서 컨테이너를 띄워 `uname -r`을 치면 `6.18.58.1-microsoft-standard-WSL2`, 즉 WSL 2의 리눅스 커널이 나와요. 그래서 도커보다 리눅스가 먼저예요.
3. **AI가 명령을 대신 쳐도, 승인은 내가 해요.** Cursor, Claude 같은 AI 코딩 도구는 터미널 명령을 제안하고, 기본 설정에서는 실행 전에 승인을 요청해요. 그 명령이 무엇을 읽고 무엇을 바꾸는지 읽을 수 있어야 승인 버튼을 누를 수 있어요. 퀴즈마다 '안전·주의·위험' 판독 문제가 들어가는 이유예요.

### 2. 운영체제, 커널, 시스템 콜

> **운영체제(OS)**: 하드웨어 자원을 관리하고, 응용 프로그램이 하드웨어를 쓸 수 있도록 공통 기능과 실행 환경을 제공하는 시스템 소프트웨어 (공통 교재 0주차)

이 정의는 두 가지 역할로 나눠 보면 선명해요.

| 역할 | 하는 일 | 예 |
| --- | --- | --- |
| 자원 관리자 | 여러 프로그램이 CPU·메모리·디스크를 충돌 없이 나눠 쓰게 조정해요 | CPU 시간을 잘게 나눠 프로그램을 번갈아 실행 (스케줄링) |
| 추상화 제공자 | 다루기 어려운 하드웨어를 다루기 쉬운 개념으로 바꿔 줘요 | CPU → **프로세스**, 메모리 → **가상 메모리**, 디스크 → **파일**, 네트워크 카드 → **소켓** |

이 일을 실제로 하는 운영체제의 핵심이 **커널**이에요.

#### 프로그램은 하드웨어를 직접 만지지 않아요

| 층 | 무엇 | 예 |
| --- | --- | --- |
| 사용자 공간 (사용자 모드) | 우리가 실행하는 프로그램 | 터미널 창, 셸(bash), `whoami` `pwd` `ls` `cat`, 웹 서버 |
| ↕ 시스템 콜 | 프로그램이 커널에 일을 부탁하는 정해진 창구 | `openat` `read` `write` `geteuid` `getcwd` |
| 커널 공간 (커널 모드) | 리눅스 커널: 자원 관리와 보호 | 프로세스, 메모리, 파일 시스템, 네트워크, 장치 드라이버 |
| 하드웨어 | 실제 장치 | CPU, 메모리, 디스크, 네트워크 카드 |

- CPU에는 권한 수준이 있어요. 일반 프로그램은 제한된 **사용자 모드**에서 돌고, 하드웨어를 직접 제어하는 명령은 **커널 모드**에서만 실행돼요.
- 그래서 프로그램은 **시스템 콜**로 커널에 부탁하고, 커널은 요청을 검사한 뒤 대신 처리해서 결과를 돌려줘요.
- 이렇게 나눈 이유는 **보호**와 **공유**예요. 한 프로그램의 실수가 시스템 전체나 남의 데이터를 망치지 않게 하고, 여러 프로그램이 장치 하나를 안전하게 나눠 쓰게 해요. 이 파일을 열어도 되는지 권한을 따지는 것도 커널이에요 (3회차 권한).

#### 눈으로 확인하기: `whoami`의 부탁

`strace`는 프로그램이 부르는 시스템 콜을 한 줄씩 보여 주는 도구예요. Ubuntu에 기본으로 깔려 있지 않아서, 아래는 Ubuntu 26.04 컨테이너에서 미리 떠 온 기록이에요.

```text
$ strace -e trace=geteuid,openat,write whoami    # 발췌
geteuid()                               = 1000
openat(AT_FDCWD, "/etc/passwd", O_RDONLY|O_CLOEXEC) = 3
write(1, "student\n", 8)                = 8
```

1. `geteuid()`: "이 프로세스의 **유효 사용자 ID**는?" 커널의 답은 `1000`이에요. 커널은 사용자를 이름이 아니라 **숫자(UID)**로 구분해요.
2. `openat(... "/etc/passwd" ...)`: 1000번이 누구인지 사용자 목록 파일에서 찾아요. 답은 `student`예요.
3. `write(1, "student\n", 8)`: "**1번**에 이 글자를 써 줘." 1번은 **표준 출력**(stdout)이고, 지금은 터미널 화면으로 이어져 있어요.

단어 하나를 출력하는 데도 시스템 콜이 100번 넘게 오가요. `strace -c`로 세어 보면 Ubuntu 24.04 컨테이너에서 127번, 26.04에서 156번이었어요. 대부분은 프로그램을 메모리에 올리고 준비하는 일이에요.

<details markdown="block">
<summary>더 깊이: 나머지 명령은 무엇을 부탁할까</summary>

```text
$ strace -e trace=getcwd,write /usr/bin/pwd
getcwd("/home/student", 512)            = 14
write(1, "/home/student\n", 14)         = 14

$ strace -e trace=openat,getdents64,write ls -a    # 발췌
openat(AT_FDCWD, ".", O_RDONLY|O_NONBLOCK|O_CLOEXEC|O_DIRECTORY) = 3
getdents64(3, 0x60f1cd2f6930 /* 5 entries */, 32768) = 144
write(1, ".\n..\n.bash_logout\n.bashrc\n.profi"..., 35) = 35
```

- **pwd**: 작업 디렉터리는 커널이 **프로세스마다** 기억하는 값이에요. `/usr/bin/pwd`는 `getcwd()`로 그 값을 물어요. 셸에서 그냥 `pwd`를 치면 bash의 **내장 명령**이 먼저 실행돼서, 셸이 기억해 둔 위치를 바로 출력해요.
- **ls**: 디렉터리를 열고(`openat`) 항목 목록을 받아요(`getdents64`). `-l`을 붙이면 항목마다 `statx`로 크기·권한·시각을 커널에 더 물어요.
- **cat**: 같은 `cat`인데 Ubuntu 버전에 따라 부탁하는 방식이 달라요 (아래는 발췌). 3번은 연 파일, 1번은 표준 출력이에요.

```text
# Ubuntu 24.04 (GNU coreutils): 프로그램이 읽어서(read) 다시 쓴다(write)
openat(AT_FDCWD, "/etc/os-release", O_RDONLY) = 3
read(3, "PRETTY_NAME=\"Ubuntu 24.04.5 LTS\""..., 131072) = 400
write(1, "PRETTY_NAME=\"Ubuntu 24.04.5 LTS\""..., 400) = 400

# Ubuntu 26.04 (uutils coreutils): 커널 안의 임시 파이프(4·5번)로 바로 옮긴다(splice)
openat(AT_FDCWD, "/etc/os-release", O_RDONLY|O_CLOEXEC) = 3
splice(3, NULL, 5, NULL, 1048576, 0)    = 410
splice(4, NULL, 1, NULL, 410, 0)        = 410
```

화면에 나오는 결과는 똑같아요. **명령의 이름과 사용법(인터페이스)이 같아도 그 명령을 만든 프로그램(구현)은 다를 수 있다**는 증거예요. 어느 쪽이든 파일과 화면은 커널을 거쳐서만 다뤄요.

### 3. Linux와 Ubuntu

- **Linux**는 엄밀히는 **커널**의 이름이에요. 넓게는 리눅스 커널을 쓰는 운영체제 전체를 부르는 말로도 써요.
- **배포판**은 커널에 기본 명령, 셸, 라이브러리, 패키지 관리자, 설정을 골라 묶은 운영체제예요. **Ubuntu**는 Debian 계열 배포판이에요.

| 연도 | 사건 | 오늘 쓰는 것과의 연결 |
| --- | --- | --- |
| 1969 | 벨 연구소에서 **Unix** 탄생 (켄 톰프슨, 데니스 리치) | 셸, 파일, 프로세스라는 기본 틀 |
| 1983 | 리처드 스톨먼이 **GNU 프로젝트** 시작. 자유 소프트웨어로 Unix 호환 운영체제를 만들자 | 셸(bash), 기본 명령, 컴파일러 |
| 1991 | 리누스 토르발스가 **Linux 커널** 공개 | GNU에 아직 완성되지 않았던 커널이 채워져 완전한 운영체제가 됨 |
| 1993 | **Debian** 시작 | Ubuntu의 바탕. 패키지 관리자 apt도 Debian에서 왔어요 |
| 2004 | **Ubuntu** 첫 출시 (Canonical) | 6개월마다 새 버전, 2년마다 장기 지원판(LTS) |

Linux는 Unix의 코드를 물려받은 게 아니라 Unix의 설계를 따라 새로 만든 **유닉스 계열**이에요. macOS도 유닉스 계열이라 터미널 명령이 비슷해요.

#### 커널과 배포판을 따로 확인하기

```text
$ uname -r                  # 커널 버전
6.18.58.1-microsoft-standard-WSL2

$ cat /etc/os-release       # 배포판 정보 (발췌)
PRETTY_NAME="Ubuntu 26.04.1 LTS"
VERSION_ID="26.04"
ID=ubuntu
ID_LIKE=debian
```

커널 이름 끝의 `microsoft-standard-WSL2`를 보세요. WSL 2는 Microsoft가 빌드한 **진짜 리눅스 커널**을 가벼운 가상 머신에서 돌리고, Ubuntu는 그 위의 사용자 공간을 맡아요. 커널과 배포판이 따로 움직인다는 증거예요. PC에 Ubuntu를 직접 설치하면 Ubuntu가 빌드한 커널이 들어가요.

#### 커널 하나, 배포판 셋 (6회차 도커 미리 보기)

같은 PC에서 컨테이너 세 개를 띄워 같은 명령을 쳤어요.

| 컨테이너 이미지 | 커널 (`uname -r`) | 배포판 (`/etc/os-release`) | 계열 (`ID_LIKE`) | `ls --version` 첫 줄 |
| --- | --- | --- | --- | --- |
| `ubuntu:24.04` | 6.18.58.1-microsoft-standard-WSL2 | Ubuntu 24.04.5 LTS | debian | ls (GNU coreutils) 9.4 |
| `ubuntu:26.04` | 같음 | Ubuntu 26.04.1 LTS | debian | ls (uutils coreutils) 0.10.0 |
| `amazonlinux:2023` | 같음 | Amazon Linux 2023 | fedora | ls (GNU coreutils) 8.32 |

1. **커널은 하나, 배포판은 셋이에요.** 컨테이너는 호스트의 커널을 함께 쓰고, 배포판(사용자 공간)만 따로 가져요. 6회차 도커 개념의 핵심이에요.
2. **같은 Ubuntu라도 `ls`를 만든 프로그램이 달라요.** Ubuntu는 25.10부터 기본 명령 묶음을 GNU coreutils(C)에서 uutils coreutils(Rust)로 바꿨어요. 어떤 부품을 넣을지 고르는 것이 배포판의 일이에요. 공통 교재에는 `whoami`가 GNU coreutils 명령으로 나오지만 26.04에서는 uutils예요. 사용법은 같게 맞춰져 있어요.
3. **Amazon Linux는 Fedora 계열이에요.** 그래서 패키지 관리자가 apt가 아니라 `dnf`예요. 처음 보는 서버에 접속하면 `cat /etc/os-release`부터 쳐 보는 이유예요.

### 4. 터미널과 셸

| 구분 | 터미널 | 셸 |
| --- | --- | --- |
| 역할 | 글자를 입력받고 결과를 보여 주는 **창** | 입력한 명령을 **해석**해 프로그램을 실행 |
| 예 | Windows Terminal, GNOME Terminal, macOS 터미널 | bash (Ubuntu 기본), zsh (macOS 기본), fish |
| 비유 | 주문 창구 | 주문을 해석해 주방에 넘기는 직원 |

- 셸도 커널이 아니라 **사용자 공간의 프로그램**이에요. 커널을 감싼 껍데기(shell)라는 뜻에서 붙은 이름이에요.
- 터미널을 열면 셸이 실행돼 입력을 기다려요. 이때 보이는 표시가 **프롬프트**예요.

```text
student@ubuntu:~$
```

| 부분 | 뜻 | bash 설정 `PS1`의 기호 |
| --- | --- | --- |
| `student` | 사용자 이름 | `\u` |
| `ubuntu` | 호스트(컴퓨터) 이름 | `\h` |
| `~` | 현재 위치. 홈 디렉터리는 `~`로 줄여 보여 줘요 | `\w` |
| `$` | 일반 사용자. 유효 사용자 ID가 0(root)이면 `#` | `\$` |

- 프롬프트 끝의 `$`와 `#`도 `whoami`가 묻는 **유효 사용자 ID**로 정해져요. `#`이 보이면 관리자 권한이니 명령을 한 번 더 읽어요.
- 명령은 프롬프트 **뒤에만** 입력해요. `student@ubuntu:~$ whoami`를 통째로 복사하지 않아요.
- 셸이 명령 이름으로 프로그램을 찾는 방법(PATH, 내장 명령)은 공통 교재 1주차에서 이어져요.

### 5. 같이 쳐 보기

오늘 명령은 모두 **읽기만** 하고 아무것도 바꾸지 않아요. 무언가 하기 전에 먼저 확인하는 습관이 오늘의 진짜 목표예요.

명령의 기본 모양은 `명령 [옵션] [인자]`예요. `ls -a /etc`라면 명령은 `ls`, 옵션은 `-a`, 인자는 `/etc`예요.

| 명령 | 사람의 질문 | 커널에게 하는 부탁 |
| --- | --- | --- |
| `whoami` | 나는 누구? | 유효 사용자 ID를 받아(`geteuid`) 이름으로 바꿔 출력 |
| `pwd` | 나는 어디? | 이 프로세스의 작업 디렉터리 (`getcwd`, bash에서는 내장 명령) |
| `ls` | 여기 뭐가 있지? | 디렉터리를 열어(`openat`) 항목 목록 받기(`getdents64`) |
| `cat /etc/os-release` | 이 시스템은 뭐지? | 파일을 열어(`openat`) 내용을 1번(표준 출력)으로 보내기 |

순서는 아래 [실습](#practice)을 따라가요.

- `ls -a`: 이름이 `.`으로 시작하면 숨김 항목이에요. 특별한 속성이 아니라 **이름 짓기 약속**이에요. `.`은 지금 디렉터리, `..`은 한 단계 위 디렉터리예요.
- `ls -l`: 맨 앞 글자가 `d`면 디렉터리, `-`면 일반 파일, `l`이면 심볼릭 링크예요. `rwx` 권한 읽기는 3회차에서 해요.
- `/etc/os-release`도 심볼릭 링크예요. `ls -l /etc/os-release`를 치면 `/etc/os-release -> ../usr/lib/os-release`가 보여요.

#### 오늘 본 1번이 MCP의 통로예요

`write(1, …)`의 1번, **표준 출력**을 2월 MCP 수업에서 다시 만나요. MCP의 stdio 방식에서는 AI 앱(클라이언트)이 MCP 서버를 **하위 프로세스**로 실행해요. AI 앱이 보내는 메시지(JSON-RPC)는 서버의 **표준 입력(0번)**으로 들어가고, 서버가 보내는 메시지는 **표준 출력(1번)**으로 나와요. 로그는 **표준 오류(2번)**에 따로 써요.

그래서 MCP 서버에서 디버깅한다고 표준 출력에 아무 글자나 찍으면 메시지가 깨져요. MCP 스펙도 서버는 표준 출력에 MCP 메시지가 아닌 것을 쓰면 안 된다고 정해 두었어요. 표준 입출력과 파이프는 4회차에서 직접 다뤄요.

### 정리

- **운영체제**는 자원 관리자이자 추상화 제공자이고, 그 핵심이 **커널**이에요.
- 프로그램은 하드웨어를 직접 만지지 않고 **시스템 콜**로 커널에 부탁해요.
- **Linux(커널)와 Ubuntu(배포판)**는 달라요. `uname -r`과 `cat /etc/os-release`로 따로 확인해요.
- **터미널**은 창이고 **셸**은 명령을 해석하는 프로그램이에요. 프롬프트는 셸이 입력을 기다린다는 표시예요.
- 배포할 서버, 컨테이너, MCP, AI가 제안하는 명령이 모두 리눅스 위에서 움직여요. 그래서 지금 리눅스를 배워요.

## 실습 (같이 쳐 보기 8분) {#practice}

1. **Ubuntu 터미널을 열어요.**
   - Windows: 시작 메뉴의 **Ubuntu**, Windows Terminal의 Ubuntu 탭, 또는 PowerShell에서 `wsl ~`
   - macOS: 교육용 Ubuntu 가상 머신에 로그인한 뒤 터미널
   - 확인: `사용자@호스트:~$` 모양의 프롬프트가 보여요.
2. `whoami`
   - 확인: 프롬프트 앞부분의 사용자 이름과 같아요.
3. `pwd`
   - 확인: `/home/내사용자이름`(홈 디렉터리)이 나와요. PowerShell에서 `~` 없이 `wsl`로 들어왔다면 `/mnt/c/…`(Windows의 C 드라이브)에서 시작했을 수 있어요.
4. `ls` → `ls -a` → `ls -l` → `ls -al`
   - 확인: `ls`에 아무것도 안 나와도 정상이에요. `ls -a`에는 `.bashrc` 같은 점 파일이 보이고, `ls -l`은 맨 앞 글자로 종류를 구분해요.
5. `cat /etc/os-release`
   - 확인: `NAME="Ubuntu"`와 `VERSION_ID`를 찾아요.
6. `uname -r`
   - 확인: 커널 버전이 나와요. WSL이면 끝에 `microsoft-standard-WSL2`가 붙어요.
7. `ls --version`
   - 확인: 첫 줄이 `GNU coreutils`인지 `uutils coreutils`인지 봐요.
8. **아래 표를 채워 첫 정리 글에 붙여요.**

| 항목 | 명령 | 내 값 |
| --- | --- | --- |
| 접속 방식 | 직접 적기 | WSL 2 / Ubuntu VM / 기타 |
| 사용자 | `whoami` | |
| 현재 위치 | `pwd` | |
| 배포판과 버전 | `cat /etc/os-release` | |
| 커널 | `uname -r` | |
| 기본 명령 묶음 | `ls --version` 첫 줄 | |

#### 막힐 때

| 증상 | 원인과 해결 |
| --- | --- |
| `whoami`에 `컴퓨터이름\사용자`처럼 역슬래시가 보이거나 `pwd`에 `C:\`가 보여요 | PowerShell(Windows)에 쳤어요. 이름이 같은 Windows 명령이 실행된 거예요. Ubuntu 창으로 옮겨요 |
| `cat /etc/os-release`에서 `C:\etc\os-release` 경로를 찾을 수 없다는 오류가 나와요 | 위와 같아요. Windows에는 이 파일이 없어요 |
| `pwd`가 `/mnt/c/…`로 나와요 | 틀린 게 아니라 WSL이 Windows 폴더에서 시작한 거예요. `exit`로 나간 뒤 `wsl ~`로 다시 열면 홈에서 시작해요 |
| `pwd`가 `/Users/…`로 나와요 | Mac 자체 터미널이에요. Ubuntu 가상 머신 안에서 쳐요 |
| `ls`가 비어 있어요 | 정상일 수 있어요. 새 계정의 홈에는 숨김 파일만 있어요. `ls -a`로 확인해요 |
| Ubuntu가 아직 없어요 | 오늘은 실습 짝 화면으로 같이 봐요. 설치는 관리자 PowerShell에서 `wsl --install` (Windows 명령이라 Ubuntu 안에서 치지 않아요) |
| Ubuntu는 없지만 Docker Desktop은 켜져 있어요 | PowerShell에서 `docker run --rm -it ubuntu:26.04`로 임시 Ubuntu를 열 수 있어요. 관리자(root)로 열려서 프롬프트가 `#`이고, `whoami`는 `root`, `pwd`는 `/`가 나와요. `exit`하면 사라져요 |
